### Features

- Project profiles: `<project>/.aide/project.json` declares which skills, MCP servers and tools a repository needs; one sync links skills into the shared and per-tool project directories and merges project-level MCP configs (Claude Code, Cursor, VS Code), only ever removing links and entries aide created itself. Configure it from the new project button in the header
- Review skills updates before applying them: the update dialog shows the added / changed / removed files between the installed copy and the upstream commit, warns when the local copy was modified, and only then lets you update
- Environment snapshots: capture the central configs plus a skill inventory under `~/.aide/snapshots`, and restore with an automatic safety snapshot; skills are never touched and drift is reported
- Portable environment bundles: export skills, MCP servers and model profile summaries to one `.aidebundle` file and import it on another machine (merge or replace). API keys and secret-looking MCP values are always redacted; a safety snapshot is taken before importing
- Health page: an aggregated environment report (skills, tools, MCP, models, config files, agent access, audit log) with one-click repairs, periodic refresh while visible, plus snapshot and bundle management
- MCP config drift detection and cleanup: `~/.aide/mcp-managed.json` records what aide wrote, so disabling or deleting a server removes exactly those entries from every tool config
- Environment audit trail at `~/.aide/audit.jsonl` for agent and high-risk operations, plus optional `AIDE_MCP_ALLOW_INSTALL` / `AIDE_MCP_ALLOW_PUBLISH` allowlists for `aide-mcp`
- Markdown preview opens external links in the system browser and resolves relative images and file links inside the skill
- Skills are re-listed when the window regains focus; update checks and skill scans are deduped and cached
- Per-OS tool config paths (Trae, VS Code) and Linux skill sync support
- OpenCode MCP and model config now resolve to the same file (`opencode.jsonc` when present)

### Fixes

- Editor edits are never lost when switching tabs, and unsaved changes are guarded when leaving a skill or switching tools
- Config writes are atomic with backups; corrupt configs are rejected instead of being silently replaced
- Publish refuses empty scopes, preserves repository files, and rescues teammate-pushed skills; pull only writes back the scope's own skills
- Skill sync backs up tool-side copies and keeps the replaced directory instead of deleting it
- Registry installs are named from SKILL.md, pinned to a commit, and enforce archive/extraction limits
- File commands are path-scoped with a sensitive-path denylist; synced tool configs are written owner-only
- Metadata commands (`list_directory`, `file_exists`, `get_file_mtime`) honor the same path policy; GUI publish/pull operations are audited

### Internal

- Headless logic extracted into the `aide-core` crate; the Tauri command layer is thin and `aide-mcp` no longer links Tauri/WebKit
- CI runs typecheck, ESLint, Vitest, `cargo fmt --check`, clippy with `-D warnings`, and tests for both crates
